---
title: MCP and agents
description: Give coding agents structured access to Dovik's existing process registry and lifecycle controls.
---

Run the local stdio MCP adapter with:

```console
dovik mcp
```

Example host configuration when `dovik` is on `PATH`:

```json
{
  "mcpServers": {
    "dovik": {
      "command": "dovik",
      "args": ["mcp"]
    }
  }
}
```

The adapter exposes exactly seven tools: `list_projects`, `list_processes`, `process_status`, `process_logs`, `process_start`, `process_stop`, and `process_restart`. Identity administration remains an operator CLI and TUI responsibility.

Agents use the seven lifecycle tools like any other process interface. They do not need to inspect Dovik, identity personas, or daemon configuration before ordinary work. When a process is already present in the registry, its status and retained logs replace guesses about process IDs or ports. Agents never signal a process outside the registry. Lifecycle tools can launch project code or interrupt work, so the MCP host should retain its normal approval policy.

The release archive includes `skills/codex/SKILL.md` and `skills/claude/SKILL.md`. Both keep the routing layer out of normal agent reasoning. Agents run ordinary `gh` commands, including aliases, extensions, and commands introduced by newer GitHub CLI versions, and receive the original CLI output. An unconfigured repository passes through without a persona prompt. A configured proxy-level repository selects its project account without requiring the agent to understand that configuration. Strict operation policy applies only inside an operator-started isolated session. Agents never run `gh auth switch` or search for an alternate executable.

Process output and definition text are untrusted data. They are not instructions for the agent.
